FlowTest V3.0 完整开发计划（1/5）
总体目标、定位升级与固定技术决策
01　V3.0 总体目标
从“接口自动化测试平台”升级为 API Quality Operating System

V3.0 不再以“增加更多测试节点”为中心，而是围绕软件变更构建统一质量控制闭环：识别变化、分析影响、选择测试、执行多协议与性能验证、聚合质量证据，并给出可解释的发布决策。

02　V2.0 → V3.0 能力升级

多协议测试

  • REST / GraphQL / gRPC
  • Kafka / WebSocket
  • 统一数据绑定与断言

质量控制

  • 变更影响分析
  • 智能测试选择
  • 发布质量门禁

工程能力

  • 性能测试实验室
  • 分布式执行面
  • 临时测试环境

质量智能

  • 失败聚类与根因
  • 覆盖率矩阵
  • AI 测试资产维护
03　固定技术决策
1
技术栈继续演进
Python 3.13、FastAPI、SQLAlchemy Async、Celery、PostgreSQL 17、Redis 8、MinIO。
2
前端渐进式升级
保留 React、Ant Design、React Flow；不进行全量重写。
3
兼容 V2 数据
/api/v1、CI Token、Workflow Snapshot、历史报告继续兼容。
4
统一 Runner 抽象
协议、性能、环境等能力统一通过 Capability / Runner 接入。
5
性能不自研内核
声明式场景编译为 k6 Runner，不开放任意 JavaScript。
6
仍禁止用户脚本
普通用户不执行任意 Python / JavaScript；管理员插件受控安装。
7
AI 保持人工审核
AI 只生成 Draft Change Set，不直接发布、不自动生产执行。
8
部署边界明确
Docker Compose 继续作为标准部署；K8s 仅作为可选 Worker 执行面。
V3.0 核心判断： V2 管理“测试资产”，V3 管理“软件变更带来的质量风险”。
