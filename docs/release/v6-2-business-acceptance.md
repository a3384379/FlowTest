# V6.2 隔离业务效果验收协议

目的：测量真实外部 LLM 使用正式 Skill/MCP 后的业务效果，不把工具可调用或已有标注评分等同于模型能力。
状态：待实际模型与接入方式确认；尚无运行成绩。

## 环境与边界

- 使用隔离 Compose、专用测试组织/账号和容器化业务 API；不连接生产数据库、不触发支付或通知。
- 业务样本不复制 v6_golden。建议使用库存预留业务：创建预留、查询、确认、只读库存核对、释放预留。
  模拟登录及外部服务；数据带运行标识，结束与取消时清理。只使用授权的 Schema、代码和脱敏 Evidence。
- 保存模型名称、模式、日期、Skill/工具版本、样本版本、运行 ID、提案 ID、Preview ID、人工修改记录。
  不保存 Token、原始敏感 Body、数据库行或密钥；取消后不自动重试产生外部副作用。
- 模型负责分析和提案；人工 Accept、一次性 Sandbox Approval、Apply/Publish 边界保持原样。
- 初期至少每类一个探索样本，不从三个样本外推总体稳定性；之后扩大独立样本再确定发布阈值。

## 三类任务

| 任务 | 输入与动作 | 必须检查 |
| --- | --- | --- |
| 首次生成 | 陌生业务契约与只读证据，经 onboarding 与旗舰 Skill 生成登录→创建→查询→断言→清理提案 | 首次编译、关联字段、断言质量、只读 DB Oracle、Preview/Cleanup |
| 失败修复 | 分别注入映射错误、数据错误、真实产品错误，使用 triage-and-repair | 前两者建议是否正确；产品缺陷不因放宽 Oracle 被掩盖；人工接受后 Re-preview |
| 变更维护 | 准备旧/新契约或约束，已有 Context 绑定的 Regression Run，使用 change-aware-regression | 受影响/未受影响流程、TestPlan Gap、维护提案范围、不完整分析显式标记 |

complete-coverage 用于首次生成后的覆盖缺口检查；所有五个 Skill 均记录实际调用情况，未用到的标为未执行。
计划外能力（自动新建完整 Run、完整结构化人工修复编辑器）不临时人工补成“模型零干预成功”。

## 记录与计算

每个样本保存：任务目标、起止时间、首次结果、最终结果、人工修改次数与分钟数、编译/Preview/Cleanup 状态、
预期与实际受影响资产 ID、修复建议是否错误、取消后的资源残留数。失败样本不可从分母删除。

| 指标 | 计算口径 |
| --- | --- |
| 首次可编译率 | 首次未经人工改写即编译成功数 / 全部生成尝试数 |
| 首次 Preview 成功率 | 首次 Preview 成功数 / 满足人工授权且尝试 Preview 的样本数，另报未获授权数 |
| 字段关联正确率 | 经独立人工核对正确的 Mapping 数 / 全部核对 Mapping 数 |
| 人工成本 | 每样本改动节点、Mapping、断言数量及人工分钟数；报告中位数与范围 |
| 影响精确率 / 召回率 | TP/(TP+FP)、TP/(TP+FN)，预先固定人工参考集合，空分母记 N/A |
| 错误修复建议率 | 被人工判定错误的建议数 / 全部建议数，产品缺陷掩盖单独列出 |
| 清理成功率 | 资源核对无残留数 / 应清理样本数，失败/取消样本亦计入 |

结果模板：`运行 ID / 模型 / 样本 / Skill / 首次结果 / 人工修改 / 最终结果 / 证据链接 / 限制`。
没有运行时填写“未执行”，不写 0%、100% 或 PASS。最终报告区分探索性验收与统计可靠性、RC 与 GA。
