# FlowTest 流程编排专项优化方案

> 文档目标：围绕 **流程编排** 模块进行专项改造，解决当前页面混乱、节点配置固定尺寸、工具栏过载、连线难以删除、快捷键缺失、UI 体验不统一等问题，并给出完整的产品方案、交互方案、前端落地方案、实施计划与配套 UI 设计稿。

---

## 1. 项目背景

当前 FlowTest 的“流程编排”已经具备基础能力：

- 工作流列表管理
- 节点拖拽与连线
- 节点配置
- 草稿 / 发布 / 运行 / 历史快照
- 多种节点类型（API、条件、断言、延迟、子流程、ForEach、协议节点等）

但从当前页面和前端实现来看，已经出现以下明显问题：

1. **画布区与配置区布局失衡**：配置面板固定宽度，画布高度固定，不能自由伸缩，影响复杂流程编排。
2. **工具栏堆叠过多按钮**：大量功能平铺，用户不知道先用什么，也不知道很多按钮的用途。
3. **节点与连线的操作心智不清晰**：节点有一定操作入口，但连线的删除、条件、映射配置入口不明显。
4. **画布交互效率偏低**：缺少 Delete、复制、粘贴、撤销、重做、Tab 新增节点、Enter 打开配置等快捷键工作流。
5. **页面视觉层级不足**：左侧工作流列表、节点库、画布、右侧配置区同时抢焦点，导致主任务不突出。
6. **运行 / 调试 / 历史差异视图没有清晰区分**：不同模式虽然存在，但整体体验不够统一。
7. **高级功能暴露过早**：GraphQL、gRPC、Kafka、WebSocket、SQL、Redis、子流程等都直接放在主工具栏，信息噪声太大。

因此，本次专项目标不是“小修小补”，而是对 **信息架构、交互结构、视觉系统、关键操作路径** 做一次系统优化。

## 2. 现状问题分析

### 2.1 页面层面问题

#### 问题一：节点配置页固定大小，无法全屏或自由调节

现状表现：

- 当前节点配置区通常固定在右侧。
- 面板尺寸较死板，复杂节点（例如 API 请求、变量映射、协议节点）配置内容很多时非常拥挤。
- 用户无法把配置区拉宽，也无法切换为全屏配置模式。

直接影响：

- 参数多时阅读困难。
- JSON / Headers / Body / 响应提取等区域空间不足。
- 配置过程中频繁滚动，效率低。

#### 问题二：功能点太多太乱，大量按钮“不知道干嘛的”

现状表现：

- 顶部工具栏与画布工具区承载过多操作。
- 高级节点入口与常用节点入口没有分层。
- 节点创建方式、接口搜索、协议节点、数据节点、控制节点混在一个平面上。

直接影响：

- 新用户上手门槛高。
- 常见流程（开始 -> API -> 断言 -> 结束）也被复杂能力淹没。
- 用户不敢点、不知道点哪个。

#### 问题三：连线删除入口不清晰

现状表现：

- 节点之间连线后，删除连线的方式不明显。
- 用户通常能选中节点，但不清楚如何选中边。
- 即使存在技术能力，也没有形成显性的交互反馈。

直接影响：

- 连线一旦错了，纠正成本很高。
- 用户容易对画布失去控制感。

#### 问题四：缺少画布级键盘快捷键

现状表现：

- 鼠标进入画布后，没有明显的快捷键操作支持。
- Delete 删除、Ctrl/Cmd+C 复制、Ctrl/Cmd+V 粘贴、Ctrl/Cmd+Z 撤销等典型工作流缺失或不明显。

直接影响：

- 编排效率低。
- 复杂流程维护成本高。
- 对有流程编排经验的用户不友好。

#### 问题五：UI 需要重新设计

现状表现：

- 各区域焦点不聚合。
- 工具按钮密度高但语义弱。
- 画布与配置之间的主次关系不清。
- 运行态、调试态、历史态缺少明显的模式感。

直接影响：

- 不专业、不清爽。
- 对平台级产品的信任感不够。

### 2.2 代码实现层面问题（结合当前前端结构）

> 以下为结合当前 FlowTest 前端结构整理出的重点改造位点。

#### 关键文件（建议重点改造）

- `frontend/src/pages/WorkflowsPage.tsx`
- `frontend/src/flow/WorkflowDesigner.tsx`
- `frontend/src/flow/WorkflowNodeInspector.tsx`
- `frontend/src/flow/WorkflowApiRequestEditor.tsx`
- `frontend/src/flow/workflow-graph.ts`
- `frontend/src/styles.css`

#### 当前已暴露的结构性问题

1. **设计器布局高度与宽度偏固定**
   - 画布高度存在固定值倾向。
   - 右侧 inspector 固定宽度，不支持拖拽调节。

2. **功能入口主要依赖按钮堆叠**
   - `WorkflowDesigner` 承载过多按钮逻辑。
   - “节点创建”与“画布操作”没有彻底分离。

3. **边（Edge）生命周期管理需要强化**
   - `workflow-graph.ts` 中已有 `connectNodes(...)` 等连接逻辑。
   - 但边选中、边删除、边条件配置、边映射配置需要形成完整交互链。

4. **快捷键系统需要独立化**
   - 当前撤销 / 重做等已有部分能力与测试覆盖，但未形成统一的键盘交互层。
   - 需要引入画布焦点与快捷键注册机制。

5. **节点配置能力强，但入口体验还不够专业**
   - `WorkflowApiRequestEditor.tsx` 已有 Drawer / 表单 / 请求预览能力。
   - 下一步应升级为“右侧简配 + 全屏配置”的双层模式。

## 3. 本次优化目标

### 3.1 总目标

将“流程编排”升级为一个更适合实际使用的 **专业流程工作台**：

- 新手可以快速上手
- 老用户可以高效编辑
- 大流程可以清晰管理
- 节点和连线都可直观操作
- 配置页既能快速改，也能全屏深度配置
- 运行、调试、历史对比视图统一且清晰

### 3.2 具体目标

1. **把画布作为主角**，页面围绕编排任务展开。
2. **把常用能力前置**，把高级能力折叠到更合理的位置。
3. **明确节点与连线的操作模型**。
4. **支持自由调节 / 全屏配置 / 快捷键编辑**。
5. **统一视觉风格与交互语言**。
6. **为后续 MCP 提案、AI 生成流程、复杂协议节点扩展留出空间**。

## 4. 方案总览

本次改造采用 “**1 个主工作台 + 4 个模式视图 + 2 类配置方式 + 1 套快捷键体系**” 的设计思路。

### 4.1 主工作台结构

主页面分为 4 个稳定区域：

1. **左侧资源区**
   - 工作流列表
   - 节点库 / 添加节点入口

2. **中间画布区**
   - 流程节点与连线
   - 缩放 / 搜索 / 自动布局 / 小地图

3. **右侧配置区**
   - 节点配置 / 连线配置 / 全局配置
   - 支持拉宽 / 收起 / 全屏配置

4. **顶部模式与操作区**
   - 编排 / 运行视图 / 历史快照
   - 保存草稿 / 发布版本 / 运行 / 调试

### 4.2 四个模式视图

1. **编排模式**：核心日常使用模式
2. **运行视图**：展示执行状态与时间线
3. **调试模式**：断点、单步执行、变量查看
4. **历史版本 / Diff 视图**：版本差异对比

### 4.3 两类配置方式

1. **右侧快速配置**：适合轻量改动
2. **全屏配置页 / Modal**：适合复杂编辑（API 节点、变量映射、协议能力）

### 4.4 快捷键体系

建立完整的编辑快捷键体系，并以“画布获得焦点”作为启用条件。

## 6. 交互设计方案

## 6.1 画布布局与尺寸方案

### 目标

解决“固定大小、不可全屏、不可自由调节”的问题。

### 改造点

1. **画布高度自适应页面剩余空间**
2. **右侧配置区支持拖拽调宽**
3. **支持隐藏 / 收起右侧配置区**
4. **支持专注模式（Focus Mode）**
5. **支持全屏画布（F）**
6. **支持节点配置全屏编辑**

### 交互规则

- 默认：左中右三栏布局
- 选中节点或连线时：右侧面板自动展开
- 无选中对象时：右侧面板展示引导说明或全局设置
- 点击“全屏配置”：打开覆盖层配置界面
- 点击“专注模式”：隐藏左侧与右侧非必要区域，仅保留画布与核心工具条

---

## 6.2 工具栏简化方案

### 当前问题

- 按钮太多，用户不知道哪些常用。

### 改造原则

1. **常用操作前置**
2. **高级能力折叠**
3. **节点创建入口统一**
4. **按“编辑 / 运行 / 调试”分组**

### 改造后工具栏结构

#### A. 顶部全局操作区

- 保存草稿
- 发布版本
- 运行
- 调试
- 更多（...）

#### B. 画布工具区

- 缩放（- / 100% / +）
- 适应画布
- 搜索节点 / API
- 自动布局
- 撤销 / 重做

#### C. 添加节点入口

不再把几十个节点能力直接平铺在主工具区，而改为：

- 一个统一的“添加节点”按钮
- 或左侧“节点库”面板展开
- 通过分类与搜索添加节点

## 6.3 节点库重构方案

### 目标

从“按钮集合”变成“可检索、可分类、可拖拽”的节点库。

### 分类建议

1. **基础节点**
   - 开始
   - 结束

2. **接口节点**
   - API 请求
   - GraphQL 请求
   - gRPC 调用

3. **数据节点**
   - SQL 只读
   - Redis 读取
   - 数据提取 / 转换

4. **逻辑节点**
   - 条件分支
   - 断言
   - 延迟
   - ForEach
   - 子流程

5. **协议节点**
   - Kafka Produce
   - Kafka Consume
   - WebSocket Exchange

### 节点卡片设计要求

每个卡片至少包含：

- 图标
- 节点名称
- 一行说明
- 拖拽添加提示 / 点击添加

### 节点新增方式

支持两种：

- **拖拽到画布**
- **点击后自动落到画布推荐位置**

## 6.4 节点与连线操作模型

## 节点操作

选中节点后显示悬浮操作条：

- 配置
- 复制
- 删除
- 更多

节点常用行为：

- 单击：选中
- 双击 / Enter：打开配置
- Delete：删除节点
- Ctrl/Cmd + C：复制节点
- Ctrl/Cmd + V：粘贴节点

## 连线操作

这是本次专项的重点之一。

### 目标

让“连线”成为一等可操作对象，而不是附属品。

### 连线选中后提供的能力

- 删除连线
- 设置条件
- 设置变量映射
- 设置标签 / 说明
- 切换成功 / 失败分支

### 连线删除设计

支持三种入口：

1. **选中连线后按 Delete**
2. **连线悬浮工具条点击“删除连线”**
3. **右侧“连线配置”面板底部删除按钮**

### 删除连线时的提示

如果该连线存在：

- 条件表达式
- 映射规则
- 分支标签

则弹出确认：

> 删除后将同时移除该连线上的条件与映射配置，此操作不可撤销。

## 6.5 快捷键方案

### 目标

当鼠标 / 焦点在画布编辑区域时，支持键盘快捷操作。

### 启用规则

- 点击画布后，画布进入焦点态
- 出现提示：**“画布已获取焦点，快捷键可用”**
- Esc 可取消当前选择

### 快捷键清单

| 快捷键 | 动作 |
|---|---|
| Delete | 删除选中节点或连线 |
| Ctrl/Cmd + C | 复制 |
| Ctrl/Cmd + V | 粘贴 |
| Ctrl/Cmd + Z | 撤销 |
| Ctrl/Cmd + Shift + Z | 重做 |
| Enter | 打开配置 |
| Tab | 快速添加节点 |
| Space（按住） | 拖动画布 |
| F | 画布全屏 |
| Esc | 取消选择 / 关闭浮层 |

### 额外建议

- 页面右侧提供“快捷键帮助”面板
- 首次进入页面时可轻提示一次
- 支持“不再提示”

## 6.7 运行 / 调试视图方案

### 目标

### 运行视图需具备

### 调试视图需具备

- 调试至断点
- 单步继续
- 重放节点
- 停止执行

## 6.8 历史版本 Diff 视图方案

### 目标

让历史快照不只是“可看”，而是“可理解”。

### 差异类型

- 新增节点（绿色）
- 修改配置（蓝色）
- 删除连线（红色）

### 辅助区域

右侧显示 **变更摘要**：

- 新增节点 n 个
- 修改配置 n 处
- 删除连线 n 条
- 导出差异报告

## 7. UI 重设计方案

## 7.1 视觉原则

1. **主任务清晰**：画布永远是视觉中心
2. **层级分明**：工作流列表 / 节点库 / 配置区不抢主焦点
3. **状态鲜明**：运行态、调试态、历史差异态有明显的视觉语言
4. **组件统一**：按钮、标签、面板、卡片保持一致的圆角、描边、阴影与间距体系
5. **可扩展**：后续 AI 提案、MCP 生成流程等入口可自然插入

## 7.2 色彩建议

- 主色：FlowTest 蓝紫色
- 辅色：
  - 成功：绿色
  - 警告：橙色
  - 错误 / 删除：红色
  - 运行中：蓝色
- 画布底色：极浅灰蓝
- 节点底色：白底 + 彩色描边 / 标签

## 7.3 节点视觉规范

- 开始：绿色
- API / 请求类：蓝色
- 数据处理：青蓝色
- 断言 / 条件：紫色
- 结束 / 危险路径：红色

## 8.2 状态模型建议

建议明确拆为以下几类状态：

1. **工作区状态**
   - 当前工作流 ID
   - 当前视图模式（draft / run / history）
   - 左侧面板展开状态
   - 右侧配置展开状态
   - 专注模式状态

2. **画布状态**
   - 当前节点集
   - 当前边集
   - 当前选中元素（node / edge / none）
   - 缩放等级
   - 画布焦点状态

3. **编辑历史状态**
   - undo 栈
   - redo 栈

4. **快捷键状态**
   - 画布是否已获取焦点
   - 是否显示快捷键帮助

## 8.3 连线删除技术方案

### 关键要求

- UI 上支持边选中
- 状态上支持删除边
- 数据上同步更新 `definition.edges`

### 建议实现

1. 在 `WorkflowDesigner` 中维护 `selectedEdgeId`
2. 监听 React Flow / xyflow 的 edge click 事件
3. 选中边后：
   - 画布中高亮边
   - 显示边操作条
   - 右侧切到 `EdgeInspector`
4. 删除边时：
   - 从 `definition.edges` 过滤掉目标 edge
   - 同步触发 `onChange(nextDefinition)`
   - 记录 undo 快照

## 8.4 快捷键技术方案

建议单独抽象：

- `useCanvasHotkeys()`
- `useWorkflowSelection()`
- `useUndoRedoHistory()`

### 关键逻辑

- 只有 `canvasFocused === true` 时响应热键
- 输入框 / 文本域内不触发 Delete、Tab 等全局编辑键
- 统一封装快捷键命令分发：
  - deleteSelection()
  - copySelection()
  - pasteSelection()
  - undo()
  - redo()
  - openInspector()

## 8.5 右侧面板拖拽调宽

### 技术建议

- 右侧 inspector 与画布使用 CSS Grid / Flex 重新组织
- 增加分隔条 drag handler
- 保存用户上次面板宽度到 localStorage

## 10. 风险与注意事项

1. **不要一次性大改所有功能逻辑**
   - 建议先做布局与交互层重构，再逐步迁移配置能力。

2. **不要让高级能力继续污染主工具栏**
   - 节点丰富没问题，但入口必须分层。

3. **边删除要处理映射规则联动提示**
   - 否则容易产生“删了线，为什么变量映射也没了”的疑问。

4. **快捷键必须处理输入框冲突**
   - 避免用户在输入文本时触发全局删除。

5. **运行态与编辑态要有明确边界**
   - 运行中原则上锁定会影响定义稳定性的编辑动作。
