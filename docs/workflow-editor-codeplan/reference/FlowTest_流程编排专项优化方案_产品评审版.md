# FlowTest 流程编排专项优化方案｜产品评审版

> 适用对象：产品、研发、测试、项目负责人、评审会议。  
> 目标：在尽量不改变 FlowTest 已有工作流能力的前提下，重构“流程编排”页面的信息架构、交互效率与视觉层级，使其从“功能堆叠页面”升级为“专业流程工作台”。

---

## 1. 本次专项为什么要做

当前 FlowTest 流程编排已经具备较完整的能力，包括：工作流草稿、发布、运行、历史快照、API 节点、断言、条件、延迟、数据集、SQL/Redis、GraphQL、gRPC、Kafka、WebSocket、子流程、ForEach 等。

问题并不在“功能不够”，而在于：

- 功能已经多到超过当前页面布局承载能力；
- 常用动作和高级动作混在一起；
- 用户很难在第一眼判断“下一步该做什么”；
- 画布不够突出，真正的主任务——编排流程——反而被周边控件挤压；
- 节点与连线的操作模型没有完全统一；
- 节点配置区对于复杂请求配置不够舒展；
- 对熟练用户缺乏快捷键和高效率编辑能力。

因此，本次建议定位为：

> **流程编排 UX 专项重构，而不是增加更多功能。**

---

## 2. 当前最明显的用户问题

### 2.1 画布空间不足

现状：

- 画布高度和右侧配置区尺寸偏固定；
- 左侧工作流、工具栏、右侧配置同时占用空间；
- 复杂流程只能不断拖拽、缩放查看。

用户感知：

> “流程一复杂，整个页面就显得挤。”

### 2.2 设置节点的入口太多、太乱

现状：

- API、GraphQL、gRPC、Kafka、WebSocket、SQL、Redis、断言、条件、延迟、子流程、ForEach 等入口平铺；
- 很多能力不是日常都需要，但一直占据主视觉区域。

用户感知：

> “很多按钮不知道干嘛，而且感觉大部分用不上。”

### 2.3 连线不像可编辑对象

现状：

- 节点容易理解“点一下配置”；
- 连线缺少明显的删除和编辑入口；
- 条件、映射等与连线相关的概念不够直观。

用户感知：

> “连错了不知道怎么删。”

### 2.4 缺少高效编辑能力

现状：

- 复制、粘贴、删除、撤销、重做更多依赖按钮；
- 没有形成标准的流程编辑器快捷键体验。

用户感知：

> “鼠标在画布里时，Delete 就应该能删。”

### 2.5 UI 层级不清

现状：

- 页面有能力，但重点不突出；
- 工具栏像“能力陈列柜”；
- 配置区、运行区、历史区样式相近，模式感弱。

---

## 3. 产品目标

### 3.1 核心目标

将“流程编排”定义成一个专业的 **Workflow Workspace**，而不是单纯的“流程页面”。

### 3.2 用户价值

改造后用户应能更快完成：

1. 新建工作流；
2. 添加 API 节点；
3. 连接节点；
4. 设置断言 / 条件；
5. 删除错误连线；
6. 配置变量映射；
7. 运行；
8. 调试；
9. 对比版本。

### 3.3 衡量标准

建议后续通过以下指标评估：

- 常用操作查找时间明显下降；
- 新用户首次完成“Start → API → Assert → End”流程的时间下降；
- 错误连线后的恢复成本下降；
- 复杂节点配置时横向滚动 / 频繁切换减少；
- 快捷键使用率逐步提高。

---

## 4. 新页面结构

推荐新的稳定结构：

```text
┌─────────────────────────────────────────────────────────────┐
│ 顶部：编排 / 运行视图 / 历史快照  +  保存 / 发布 / 运行 / 调试 │
├──────────────┬──────────────────────────────┬───────────────┤
│ 工作流 / 节点库 │           主画布             │ 节点/连线配置   │
│ 可收起        │      最大化、可全屏            │ 可调宽、可全屏   │
│              │                                │               │
└──────────────┴──────────────────────────────┴───────────────┘
```

原则：

- 画布永远是主角；
- 左右两侧都是辅助区；
- 高级能力默认不全部展开；
- 选中什么，就配置什么。

---

## 5. 关键产品设计决策

## 5.1 工具栏从“平铺按钮”改为“任务分组”

保留在主界面的只有：

- 保存草稿
- 发布版本
- 运行
- 调试
- 添加节点
- 搜索
- 撤销 / 重做
- 自动布局

其余节点类型统一进入“添加节点”面板。

### 好处

- 首屏更干净；
- 不再要求用户理解所有能力；
- 高级节点仍然保留，但不再持续占据视觉空间。

---

## 5.2 节点库改为分类 + 搜索

分类：

- 基础节点
- 接口节点
- 数据节点
- 逻辑节点
- 协议节点
- 工具节点

用户可以：

- 搜索节点；
- 拖拽添加；
- 点击快速添加。

---

## 5.3 节点配置采用“双模式”

### 快速配置

右侧 Inspector：

- 改名称
- 改基础参数
- 改断言
- 改映射摘要

### 深度配置

点击“全屏配置”：

- API Params
- Headers
- Body
- Variables
- Retry
- Timeout
- Preview

### 产品意义

既照顾简单操作，也照顾复杂请求。

---

## 5.4 连线升级为一等对象

连线不再只是“线”，而是具备配置能力的 Edge：

- 条件
- 标签
- 变量映射
- 成功 / 失败路径
- 删除

### 删除入口

- Delete 快捷键
- 连线浮动工具条
- 右侧配置面板

---

## 5.5 引入画布焦点和快捷键

当用户点击画布后：

- 页面提示“画布已获取焦点，快捷键可用”；
- Delete 删除选中对象；
- Ctrl/Cmd + C / V 复制粘贴；
- Ctrl/Cmd + Z 撤销；
- Ctrl/Cmd + Shift + Z 重做；
- Enter 打开配置；
- Tab 快速添加节点；
- F 全屏；
- Esc 取消选择。

---

## 5.6 引入“专注模式”

用途：

- 复杂流程编排；
- 演示流程；
- 调整节点位置；
- 专注连线。

开启后：

- 收起左侧工作流 / 节点库；
- 收起右侧配置区；
- 画布最大化；
- 只保留核心操作条。

---

## 6. 运行 / 调试体验

### 运行视图

节点状态：

- 已通过
- 运行中
- 等待
- 失败
- 跳过

辅助信息：

- 执行时间线
- 请求 / 响应
- 节点输出
- 变量快照
- 执行日志

### 调试视图

新增或强化：

- 调试至断点
- 单步继续
- 重放节点
- 停止
- 查看节点变量
- 查看请求 / 响应

---

## 7. 历史版本 / Diff 体验

版本对比支持：

- 新增节点：绿色
- 修改配置：蓝色
- 删除节点 / 连线：红色
- 未变化：灰色

右侧提供变更摘要：

- 新增节点数量
- 修改配置数量
- 删除连线数量
- 具体差异项

---

## 8. 产品优先级

### P0

- 连线可选中、可删除
- Delete / Copy / Paste / Undo / Redo
- 右侧 Inspector 可拖拽调宽
- 工具栏瘦身
- 画布自适应高度

### P1

- 节点库重构
- 全屏配置
- 专注模式
- 连线配置面板
- 运行 / 调试体验统一

### P2

- 版本 Diff 增强
- 快捷键帮助面板
- 导出差异报告

---

## 9. 推荐迭代拆分

### Sprint A：核心可用性

- 连线删除
- 快捷键
- 右侧可调宽
- 画布自适应
- 工具栏瘦身

### Sprint B：结构重构

- 节点库
- 全屏配置
- 连线 Inspector
- 专注模式

### Sprint C：高级体验

- 运行 / 调试
- 历史 Diff
- 快捷键帮助
- 差异报告

---

## 10. 产品验收标准

### 基本验收

- 用户 3 秒内能找到“添加节点”；
- 用户能直接点击连线并删除；
- 用户能通过 Delete 删除选中节点或连线；
- 用户能把配置区拉宽；
- 用户能进入全屏配置；
- 页面视觉焦点明显落在画布；
- 常用动作不再被高级能力淹没。

### 体验验收

- 主工具栏显著减少；
- 添加节点路径更统一；
- 连线操作有明确反馈；
- 复杂流程可使用专注模式；
- 运行、调试、历史三种模式具有明显视觉区分。

## 12. 评审结论建议

建议本专项立项，并采用：

> **先解决“画布、连线、快捷键、配置区”四个高频痛点，再逐步重构节点库、运行视图与历史 Diff。**

不建议继续在当前顶部区域追加更多按钮，也不建议继续把新增能力以平铺方式暴露在主界面。
