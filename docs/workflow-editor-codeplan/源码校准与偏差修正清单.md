## 1. 结论与范围

前面的产品方案与图适合表达方向，但不足以直接作为实现规格：有的交互没有接到领域状态，有的图元素与服务端模型矛盾，有的“优化”会让已生成测试定义丢字段。

本次优先固定既有数据/执行契约，再约束交互、组件和验收。主方案是新的实施依据；旧三份方案保留在 reference/ 供历史对照，不是与新方案同优先级的任务列表。

只对本功能相关的20个文件建立来源清单。没有宣称全仓库全量审计，也没有运行编译、应用单测、真实浏览器E2E或业务接口。依赖声明已读取，实际lockfile与本地安装类型由T00补核对。

## 4. 几个不能“自动修好”的边界

### 4.1 删除上游节点的依赖

明确source_node_id/cleanup_for引用可以定位；模板字符串和未知capability表达式不能靠全文replace自动重写。方案要求阻断明确危险引用，对无法完备分析的部分提示或保守阻断，不假装已经证明没有影响。

### 4.2 服务端发布并发

当前页面publish调用没有传expected_revision。前端先检查一次revision不能形成与publish的服务端原子性；不能在方案中承诺解决所有跨用户发布竞争。本期保留显式版本和本地未保存提示；若将来要增强发布原子契约，应单列后端任务与测试。

### 4.3 当前节点最终请求预览

现有preview函数支持部分覆盖和service/endpoint，但不代表已实现完整上游上下文、所有请求抑制、Body kind切换等效运行。方案对不能表达的配置显示限制或不提供误导性预览，而不是调用一遍真实业务来“补齐”。

### 4.4 不完整本地流程

编辑时删除边是一种中间状态，不能立刻强迫用户恢复完整图。但它不等于已满足服务端创建/保存/发布的图校验。不同状态分别标示，不能用统一“已保存”掩盖失败。

### 4.5 图形历史Diff和实时调试

保留已有版本Diff、历史快照和断点前运行是本期回归目标；把概念图中的高级界面做成完整新功能不是原五项诉求的必要条件。不为好看添加无后端支持的按钮。

## 5. Codex 偏差检测表

每个阶段交付时搜索以下反模式：

| 反模式 | 为什么阻断 |
|---|---|
| 仅新增demo/HTML路由，原WorkflowsPage未改 | 没解决真实使用问题 |
| Nodes/Edges由ReactFlow JSON直接提交 | UI字段污染严格后端模型 |
| 多套onChange绕过command | Undo不完整、异步覆盖、草稿不同步 |
| 按position事件逐帧localStorage | 拖动历史膨胀与同步IO压力 |
| request_overrides按可见控件重建 | 负向认证和MCP测试语义可能丢失 |
| 提取器/断言默认source=End | 与人工编排来源不符 |
| source/target改完不改mapping ID | 服务端约束冲突 |
| 跨phase边自动串起来 | 清理与主执行语义混淆 |
| 表单size变化改key | 最大化丢输入 |
| 用默认props假装只读 | 快捷键/重连仍可能改图 |
| 新unsafe使用旧draftScope key | 解除其他未保存内容的保护 |
| 只markUnsafe但不保留表单raw | 离页仍丢值，提示变假 |
| 空it/expect(true)/删除失败测试 | 没有可验证实现 |
| fake step/响应200写死/只做静态图 | 超出真实后端契约或伪功能 |
| 升级包/全局overflow hidden顺便改其他页面 | 范围扩散和回归风险 |

## 6. 文档和实现的变更规则

实施中若发现本方案的具体props与锁定库不符，可采用等价API，但必须登记“原计划符号 -> 真实符号 -> 保持的行为 -> 测试”。若发现后端契约已演进，先更新source-baseline与本修正清单，再更新计划，不继续机械执行旧细节。

不能因为某模型做不到某一实现，就把验收目标改成它已生成的页面。可调整组件内部划分；不可降低字段保留、可撤销、焦点保护、模式只读和服务端真实状态等目标。
