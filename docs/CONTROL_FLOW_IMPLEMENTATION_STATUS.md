## 基线与契约

- 从 `origin/main` 的 `ee57f6795c644e9c6d62d9d20ce5442831a613b6` 创建分支，之后已合入 `origin/main` 的 `f2aa81d`；同步后后端全量测试和前端门禁均通过。
- 保留旧流程 schema `1.0`、`2.0`、`3.0` 和旧引用型 ForEach 的默认行为。内联控制区域使用 schema `4.0`、`flow.control.*@1.0.0`，要求显式主请求预算。
- 区域拥有稳定 ID、owner、role、入口、出口、独立 DAG；定义节点不按运行轮次复制。运行轮次通过实例 ID 和 checkpoint 表示。
- schema `4.0` 的定义可以表达固定版本引用体，但发布时明确拒绝；当前只执行内联区域。

控制块模板共 11 类：集合遍历、重复次数、IF、Switch、While、DoWhile、Until、Parallel、Try、步骤组、主动失败。Break、Continue、Return 已有运行契约；Break/Continue 可在直接所属的串行循环体内通过面板添加，Return 尚无安全的普通画布添加入口。面板提供配置与区域 JSON 编辑，并能可视化修改等待步骤的时长、向串行区域追加等待和固定版本的接口步骤；未应用的区域 JSON 草稿会锁定这些可视化操作，外部更新不会静默覆盖草稿。区域画布现可显示内部连线与入口、出口，拖动节点并保存位置；选中串行区域步骤后可在安全连线中插入等待或固定版本的接口步骤，有条件或字段映射的连线会拒绝直接插入。任意内部连线编辑、步骤删除与重排、嵌套控制可视化、区域边界折叠仍未完成。选中无字段映射的主画布连线后添加控制块，可在一次编辑中完成插入与自动布局；有映射的连线会拒绝直接插入。主画布中有单一入口、出口的普通节点可包装为步骤组或集合遍历，保留原节点 ID；仅无输入、输出、映射、嵌套和外部引用的单步骤控制块可确认后拆解。

## 兼容、部署与风险

- S6 派生运行新增 Alembic `20260925_0056`，保存来源运行、循环节点和原始轮次索引；实例记录继续复用现有 checkpoint 表。已在隔离 PostgreSQL 上验证完整升级链以及从 `0056` 降级再升级。Runner Fabric 的 schema `4.0` 任务要求显式 `flow.workflow.schema4`，旧 Runner 不会领取该任务。现存 Runner Pool 如只允许 `flow.workflow`，管理员需要先通过 Pool 更新接口追加新能力，再注册新版 Runner；排队任务不会自动降级到旧 Runner。
- 内联子节点在一次区域执行中写入 checkpoint。恢复时，schema `4.0` 中预留了请求但没有终态 checkpoint 的非只读叶子会标记 `SIDE_EFFECT_OUTCOME_UNKNOWN`，停止后续主流程请求；未知结果不能被 Try/Catch 当作业务失败处理，Finally 仍按清理策略运行。固定版本 GET 与经只读校验的 SQL/Redis 叶子可重试。顶层 ForEach 的失败项已有受限派生入口，未知写入须人工查证后显式允许重试；尚无原运行中继续执行的入口，也尚未完成任意进程崩溃点的持久化端到端证明。不能宣称外部副作用只发生一次或已经回滚。
- 单进程共享许可不等于跨 worker 全局限流。并发控制能力目前适合受控验证，不应据此承诺分布式全局 QPS。
- 实例分页接口按 checkpoint 分页，运行面板分页只限制呈现的轮次选项；主运行报告的 `items` 仍随父节点输出整体返回，大轮次报告的端到端按需加载尚未完成。
- AI provider 契约仅允许空 `regions`，明确不生成或修改内联区域；旧 AI 草稿保持原有行为。
- 旧“重放节点”接口对 schema `4.0` 返回 `CONTROL_REPLAY_REQUIRES_DERIVED_RUN`。新增派生入口只接受原始、终态、单次正式运行中顶层内联 ForEach 报告明确失败的 `input_index`；新执行记录保存来源运行 ID、循环节点和原始索引，使用原加密计划与上游 checkpoint，不重新获取集合。选中轮次内已成功的步骤 checkpoint 复用，未知或失败的外部写入默认拒绝重试，显式查证后才允许；复用成功写操作的输出须确认资源仍有效。派生运行只调度所选循环及已恢复的上游节点，跳过原下游节点。当前还不支持嵌套控制、流程级 cleanup、数据集批量运行、从派生运行再次派生；这些请求明确返回 409，不应声称全场景失败项重跑完成。
- FlowSpec v1/v2 无法保真承载内联区域；导出和以控制流工作流为目标的导入明确返回 `FLOWSPEC_CONTROL_UNSUPPORTED`，避免丢失区域后声称转换成功。原生工作流定义、版本快照和实例记录保留区域。
- 目前仍为开发分支；未形成 S1–S6 的发布就绪结论。
