控制块模板共 11 类：集合遍历、重复次数、IF、Switch、While、DoWhile、Until、Parallel、Try、步骤组、主动失败。Break、Continue、Return 已有运行契约；Break/Continue 可在直接所属的串行循环体内通过面板添加，Return 尚无安全的普通画布添加入口。面板提供配置与区域 JSON 编辑，并能可视化修改等待步骤的时长、向串行区域追加等待步骤；未应用的区域 JSON 草稿会锁定这些可视化操作，避免被覆盖。尚未实现设计文档要求的完整内联区域画布编辑。选中无字段映射的连线后添加控制块，可在一次编辑中完成插入与自动布局；有映射的连线会拒绝直接插入。

## 兼容、部署与风险

- 本阶段没有数据库结构变更；实例记录复用现有 checkpoint 持久化。Runner Fabric 的 schema `4.0` 任务要求显式 `flow.workflow.schema4`，旧 Runner 不会领取该任务。现存 Runner Pool 如只允许 `flow.workflow`，管理员需要先通过 Pool 更新接口追加新能力，再注册新版 Runner；排队任务不会自动降级到旧 Runner。
- 内联子节点在一次区域执行中写入 checkpoint；尚未证明任意进程崩溃点的外部副作用只发生一次。对于已送达外部系统、结果不确定的写操作，不能自动重发或宣称回滚。
- 单进程共享许可不等于跨 worker 全局限流。并发控制能力目前适合受控验证，不应据此承诺分布式全局 QPS。
- 实例分页接口按 checkpoint 分页，运行面板分页只限制呈现的轮次选项；主运行报告的 `items` 仍随父节点输出整体返回，大轮次报告的端到端按需加载尚未完成。
- AI provider 契约仅允许空 `regions`，明确不生成或修改内联区域；旧 AI 草稿保持原有行为。
- 旧“重放节点”接口对 schema `4.0` 返回 `CONTROL_REPLAY_REQUIRES_DERIVED_RUN`，避免默认重发上游写操作；按冻结输入选择失败项并创建派生运行尚未实现。
- FlowSpec v1/v2 无法保真承载内联区域；导出和以控制流工作流为目标的导入明确返回 `FLOWSPEC_CONTROL_UNSUPPORTED`，避免丢失区域后声称转换成功。原生工作流定义、版本快照和实例记录保留区域。
- 目前仍为开发分支；未形成 S1–S6 的发布就绪结论。
