```text

核心验收不是“出现页签栏”，而是：

2. 页签/草稿按 server instance + user + project + resource type + resource id 隔离。新建未保存资源有稳定临时 ID。
3. focus 对应真实资源，proposal 对应独立提案；同路由不同资源不能被误合并。搜索关键字变化不应无意义开新页签。
4. 支持激活、关闭、关闭其他、关闭全部非固定页签，dirty 标记和保存/丢弃/取消。批量关闭也不能丢未保存内容。
5. 同一项目多个工作流可独立编辑；跨项目页签激活时同步正确项目上下文。不能把旧项目草稿带新 project_id 保存。
6. 将现有局部 draftEdit 改为外部、按资源隔离的状态。保留节点、连线、坐标、参数、映射、选择和关键画布视图。同会话切页保留撤销记录，不要求无限历史落盘。
7. 使用适合结构化草稿的 IndexedDB 或项目已有等价机制；保存 schema version、base revision、更新时间与编辑版本。
8. 自动保存只写本地草稿，不自动发布。处理防抖尚未落盘就切页/刷新、异步旧写覆盖新写、空间不足、存储不可用等情况，失败不能显示“已保存”。
9. 服务端保存继续使用 expected_revision；远端变更时保留本地草稿并提示冲突。保存响应回来的时候有更晚本地编辑，不得误清 dirty。
10. 变量新增使相关查询失效，回到流程立即可选择，不能为刷新变量重置草稿。
11. 接入 S3 删除：删除资源关闭页签、清理草稿、阻止延迟写复活。登出清理会话和草稿，换用户不得读取前用户内容。
12. 脱敏 OFF 的草稿保持原值，不另加前端自动遮盖；不额外复制 Secret 存储或未授权数据。

先补会失败的关键前端/E2E 用例，再实现：
- 工作流→变量→工作流，核对内容和新增变量。
- 同项目 A/B 工作流互不覆盖；两个项目同名工作流互不污染。
- 立即切换、刷新、前进后退、恢复草稿；存储异常提示。
- 关闭/关闭其他/全部关闭的 dirty 确认。
- refetch 与服务端冲突；保存响应与新编辑竞争。
- 删除时有排队保存；登出换用户；必要的多浏览器窗口冲突。
- 变更环境不丢草稿，实际执行仍满足 S1。

避免让每个业务页面自己维护一套并行缓存。先选稳定最小方案，不做拖动页签排序、窗口分屏或复杂跨端同步。

运行相关格式、lint、类型、前端测试/build 和可用 E2E；不操作真实业务系统。更新 checkpoint，说明恢复边界与未执行测试，完成 S4 后停止。
```

```text
性能边界：
```
