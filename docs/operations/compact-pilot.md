# Compact 公司试点与长时观察

本清单用于 V4 S34～S35 公司内网试点。自动化通过只能证明工具可用，不能代替真实网络、
安全审批、用户操作和时间窗口。

## 试点前

1. 指定业务负责人、平台运维、安全审批人和回滚执行人，记录联系方式与变更窗口。
2. 确认主机至少 2 CPU、4 GB 内存和 10 GB 可用磁盘，并为 Artifact 保留量额外规划空间。
3. 仅通过受信渠道取得离线包摘要，核对架构、`SOURCE_REVISION`、镜像 ID 和安全扫描结论。
4. 完成内网 IP/DNS、TLS、防火墙、出站白名单、备份位置和 `.env`/加密密钥托管审批。
5. 首次导入前完成一次空环境安装、备份、恢复和 Full↔Compact 兼容演练。
6. 在维护窗口运行 `drill_rollback.sh`，确认一次性资产被回滚、恢复后可写入且最终回到演练前基线。
7. 使用候选离线包完成一次失败注入和一次正常升级，分别保留 `rolled_back` 与 `passed` 证据。

## 试点期间

1. 先运行 `benchmark.sh`，保留 API 吞吐/P95、Workflow 吞吐/P95、队列深度和容器资源快照。
2. 运行至少 72 小时 `soak.sh`。期间不人工重启容器、清空 Redis 或修改证据文件。
3. 每天执行一次真实样例：导入 API、上传/下载 Artifact、发布 Workflow、并发执行与报告查看。
4. 记录用户数、项目数、Artifact 总量、每日执行数、P95、失败率、容器重启、磁盘增长与所有人工干预。
5. 任何证书错误、数据丢失、无法解密、持续队列积压、非计划重启或越权都立即终止试点并进入回滚。
6. 发生异常时运行 `collect_support_bundle.sh`；发送前人工检查白名单目录，不把 `.env` 或原始日志附入工单。

## 退出与签署

- 72 小时探针失败数为 0、容器重启增量为 0、期末队列深度为 0。
- 备份恢复后 Artifact 哈希、Project 数据和 Workflow Execution Snapshot 一致。
- Full↔Compact 双向验收证据为 `passed`，公司目标浏览器的核心页面回归通过。
- 回滚演练证据为 `passed`，诊断目录通过文件白名单、隐私边界与逐文件摘要校验。
- 失败升级自动恢复旧镜像/数据且保持非零退出，正常升级证据为 `passed` 并通过核心业务 smoke。
- 业务负责人、运维和安全审批人共同签署试点结果、未解决风险和容量边界。

S34～S35 试点通过不等于 V4 正式发布。正式 RC 仍需要连续 14 天观察及既有 Full 发布门槛。
