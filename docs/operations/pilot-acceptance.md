# V1.0 试点验收记录

## 自动化验收范围

- Mock 业务链路：登录 → 提取 Token → 查询用户 / 创建订单 → 断言 → 报告下钻。
- 执行行为：成功、HTTP 失败、5xx 重试、超时、依赖并行、运行中取消。
- 安全治理：Viewer 只读拒绝、Secret/Token 持久化脱敏、SSRF、限流、幂等与审计。
- 运维：readiness、Prometheus 指标、90 天清理、容量门槛、依赖/镜像扫描、备份和隔离恢复。

## 发布门槛

- 后端覆盖率不低于 85%，执行与安全关键模块保持高覆盖。
- 前端语句覆盖率不低于 75%，变量/工作流状态关键模块不低于 90%。
- S3–S11 Compose 冒烟、浏览器主路径、容量测试和恢复演练全部通过。
- Ruff、mypy strict、依赖边界、ESLint、TypeScript、依赖审计和镜像扫描全部通过。
- 没有未处理的 P0 缺陷；每项失败都必须在 PR 中说明风险和回滚方法。

自动化门槛用于确认构建可发布；原计划中的“两周连续试点运行”属于上线后的时间性观察，
不能由单次 CI 伪造。团队应在正式内部环境连续观察两周并记录可用性、失败分类和容量趋势。
