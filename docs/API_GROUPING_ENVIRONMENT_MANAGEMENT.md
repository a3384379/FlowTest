# 接口分组与环境管理

## 操作入口

接口页顶栏的「管理环境」打开项目环境抽屉。请求区的「发送环境」仍用于选择实际调试目标。

接口目录支持三种移组入口：

- 勾选列表中的多个接口，点击「批量移动」。翻页和筛选保留选择，工具条显示本页与其他页数量。
- 点击分组名称右侧的加号，在项目接口目录中搜索、按方法筛选并跨页选择接口移入此分组。已有成员不可重复勾选。
- 「移动接口」移动当前正在查看的单个接口。

目标分组使用完整父子路径，也可以选择「未分组」。批量移动上限为 1000 个接口，后端一次性校验并提交；目标分组或任一接口不可用时整批失败。移动只更改归属，保留接口 ID、版本、用例引用和执行历史。

## 环境抽屉

左侧列出当前项目的环境，标记实际发送环境。右侧显示正在编辑的环境，包含基本信息、变量与请求头、服务地址三个标签页。

- 浏览、创建和保存环境不会自动切换发送目标。「用此环境调试」才会明确切换。
- 变量与请求头默认使用名称和值表格，可切换高级 JSON。保存前校验名称、重复键和字符串值。
- 服务地址支持为已有服务创建和编辑 Endpoint Variant、地址及启用状态；编辑保留请求头、变量、密钥引用、TLS 和超时等原有设置。完整服务目录和高级地址设置继续使用「服务目录」与「请求目标」模块。
- 保存环境或服务地址后，重新获取环境、地址目录和后端请求目标预览，避免继续显示旧的最终地址。
- 切换编辑环境或关闭时，未保存修改需要明确丢弃。保存失败保留修改；环境列表刷新失败也保留已打开的编辑器。
- 删除发送环境后显示「原环境已失效，请重新选择」，发送保持禁用。历史执行和快照保留。
- 只读成员可以浏览配置，创建、保存、删除和应用调试环境均禁用。查看冻结执行历史时不能应用发送目标。

## 验证范围

命名回归覆盖跨页勾选、整批校验与失败回滚、项目权限、目录版本元数据、环境创建与发送选择隔离、失效环境、未保存提示、刷新失败和服务地址局部更新。

本次在隔离 Compose 预览中使用合成项目、53 个接口和两个环境验证真实交互，并在 PostgreSQL 上验证有重叠接口的并发批量移动及版本保留。原有本地部署及用户数据不参与验收。

本地全量检查、最新提交的 GitHub Required Gate、合并后的主分支 CI 和正式部署验收是独立阶段；本文件不代表正式环境发布或发布签字。
