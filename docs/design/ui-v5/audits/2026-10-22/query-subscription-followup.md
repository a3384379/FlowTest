# FlowTest 权限缓存订阅追加审计与修复方案

日期：2026-10-22。关联 [PR #149](https://github.com/a3384379/FlowTest/pull/149)、[组织切换边界审计](scope-followup-audit.md)及[实现记录](scope-followup-implementation.md)。追加修复基线：`c8ff3e81274f026d007ab16bc804c4bcf42bd733`。

## 1. 追加审计发现

编号：C-GLOBAL-02，严重程度 P2。权限 hook `useQueryInvalidated` 直接订阅所有 QueryCache 事件，未区分目标查询和 invalidation 状态是否真的变化。父组件已读取新快照、尚未提交时，子组件创建或更新其他查询 observer 会再次同步通知父订阅，触发 React 的渲染期跨组件更新告警。

实际路径是项目权限刷新返回 403，以及组织往返后的权限读取返回 503。触发告警的事件分别是 `project-members` 和 `folders` 的 `observerResultsUpdated`；父组件实际订阅的是权限查询。现有业务断言仍通过，但重复父更新违反 React 的渲染约束。尚未证明权限误开放、数据丢失或跨组织读取。

这不是原始基线的历史告警。独立 max 对照采用同一个既有 403 业务用例，保留全部业务断言，仅复用已审查的定位提速：`104e09f` 完整源码快照通过且零告警，`a6b4d89` 产品快照在完成业务断言后，因两条 React 告警而未通过零告警断言。首次终审将旧失败 CI 轮次中已出现的告警当作历史问题，归属判断不充分，本节明确更正。

## 2. 影响范围与修复边界

实际消费者包括项目治理、共享权限能力、工作流、测试资产及报告通知的写入口。追加修复只调整共享 hook 的订阅精度，并补行为测试；不修改权限角色优先级、会话身份隔离、组织切换恢复、命令重发策略或后端授权。

不能通过延后所有通知消除告警。权限显式失效必须继续同步通知消费者，保证原有失效期间关闭写入口的合同；普通自然 stale、后台读取和非目标查询事件保持原行为。

## 3. 详细修改方案

1. 使用 QueryClient 解析后的目标 query hash，遵循项目配置的 `queryKeyHashFn`，避免默认哈希与实际查询不一致。
2. 每个订阅只处理目标 query hash 的事件，排除成员、目录等无关查询的 observer 元数据通知。
3. 在订阅闭包中保留上一次真实 `isInvalidated` 布尔值，只有实际状态变化时同步通知 React，避免已通知的状态又被 metadata 事件重复送达。
4. 从当前 QueryCache 读取状态，正确处理目标查询移除、重建、成功读取及 reset；不能使用 removed 事件中已脱离缓存的旧 Query 状态。
5. 查询 key 或 QueryClient 切换时清理旧订阅；新订阅读取当前目标快照。保持 `useSyncExternalStore` 的提交前一致性检查，不引入异步权限窗口。

## 4. 行为验收

- 保留真实父权限消费者及子 `useQuery` 恢复挂载的渲染路径，修复前应出现告警，修复后父状态正确且零渲染期跨组件更新告警。
- 显式 invalidation 仍同步关闭写入口；普通自然 stale 和后台读取不会被误判为权限失效。
- 非目标查询新增、observer 更新及数据更新不会重复通知目标权限消费者。
- 自定义 query hash、目标移除和重建、key/QueryClient 切换继续读取准确状态，旧查询事件不污染新目标。
- 既有项目 403/503、成员自移除、组织切换、权限 pending 和慢刷新输入保护用例保持；共享实际消费者继续回归。
