# 测试资产原生包

原生包用于交接用例和套件，包含草稿、完整已发布版本、固定引用、目录引用、标签、说明和用例模板属性。套件导出会带上其草稿及历史版本引用的全部依赖用例。

## 工作区操作

1. 在当前页选择用例或套件，点击“导出所选”。导出范围由当前选择确定，套件依赖会完整打包。
2. 点击“导入原生包”，选择 JSON 文件。服务端先校验契约、内容指纹、版本序列和依赖，再展示预览。
3. 为每项资产选择新建、另存名称、更新已有资产或跳过。名称冲突及已归档对象会在预览中阻止提交。
4. 在目标项目选择流程、已发布流程版本、环境和目录。相同项目可以复用原引用；跨项目绑定需要明确指定。目录可以绑定现有目录或明确归为未分类。
5. 重新预览，核对目标对象、固定版本映射、覆盖范围和流程内容差异，勾选确认后导入。

修改策略、名称或资源绑定会使旧预览失效。提交时会重新核对目标资产的完整内容指纹；其他窗口的说明、标签、目录、草稿或版本修改都会要求重新预览。写入失败保留文件与配置，并撤销整批数据库写入。

## 版本与引用

源包的用例和套件版本必须从 1 开始完整递增，每个版本都带内容指纹和变更说明。已发布套件必须固定每个成员的用例版本，已发布用例必须固定流程版本。

新建资产保持源版本序列。更新已有资产时，内容及变更说明完全相同的版本可以复用，缺失版本追加为新的目标版本；原有已发布版本、计划和执行历史保持原引用。预览及导入响应返回每个源版本到目标版本的映射，套件使用映射后的用例 ID 和版本。目标版本的创建人与时间记录本次导入行为。

“跳过”保留目标资产的元数据和草稿，仅复用内容及说明一致的已有固定版本；缺失匹配版本时会阻止导入。待新建用例不能绑定到跳过复用的既有套件版本。

流程绑定校验目标项目和已发布版本。目标流程指纹与源引用不同时，需要显式选定版本，预览会显示差异。流程和环境使用目标项目现有资源；导入完成后，执行仍通过资产工作区的运行或加入计划操作发起。

## HTTP 契约

所有端点位于 `/api/v1/projects/{project_id}`，沿用项目权限与标准错误信封、追踪 ID。

| 端点 | 请求 | 响应 |
| --- | --- | --- |
| `POST /test-assets/export` | `case_ids`、`suite_ids`，至少选择一项 | 原生 JSON 附件 |
| `POST /test-assets/import/preview` | `package`、`choices`、`bindings` | 预览指纹、能否提交、逐项冲突、依赖绑定和版本映射 |
| `POST /test-assets/import/apply` | 相同包及配置，增加 `expected_preview_fingerprint` | 整批资产 ID 和固定版本映射 |

包标记为 `format: "flowtest-test-assets"`、整数 `format_version: 1`。其余顶层字段为 `source_project_id`、`folders`、`environments`、`workflows`、`cases`、`suites`，结构见 [契约定义](../../../backend/app/schemas/test_asset_packages.py)。未知字段、重复 ID、循环目录、缺失引用、不连续版本、错误内容指纹及非法 Header 都会拒绝。

`choices` 每项使用 `kind`、`source_id`、`action`，可选 `name` 和 `target_id`。`bindings.workflows` 以源流程 ID 为键，值含 `target_id` 和源版本到目标版本的 `versions`；环境绑定为源 ID 到目标 ID，目录绑定为源 ID 到目标 ID 或 `null`。

包及请求上限为 10 MiB；导出最多明确选择 100 个用例和 100 个套件，依赖闭包最多 500 个用例，每项资产最多 1000 个版本。超限会返回明确错误。导入需要项目编辑权限；项目只读成员可以导出已授权的资产。包中环境仅含 ID 和名称，Secret 资源的值继续遵守现有只写边界。

## 已执行验证

- 后端公开 HTTP 行为：版本往返、套件固定引用、同秒修改说明后的过期预览、套件写入失败整批回滚、跨项目资源绑定、只读权限、请求上限和严格输入校验。
- 前端行为：选择文件、服务端契约校验、准确导出范围、显式确认、配置修改使旧预览失效、缺失绑定阻止提交、失败保留输入、响应范围核对和下载 URL 回收。

定向验证记录对应审计清单 C01。综合浏览器验收和最新提交的远程合并门禁另行记录。
