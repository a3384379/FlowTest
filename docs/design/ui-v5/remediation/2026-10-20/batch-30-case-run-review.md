## 发现与修复

1. **发布版本的运行目标曾被草稿替代。** 例如用例 v1 固定生产环境 P，服务器草稿已改为测试环境 T；选择运行 v1 时，旧确认区仍显示 T，实际执行按 v1 使用 P。确认信息现由运行来源和所选发布版本的完整 `definition` 决定，展示对应流程、流程版本与环境。切换历史版本或草稿时即时更新；未选择来源、版本定义加载中或读取失败时，不显示草稿目标充当发布版本目标。
2. **临时提交失败曾使按钮永久禁用。** 提交错误和版本读取错误现分开处理。503 后保留来源、版本和错误提示，用户可以留在原弹窗手工重试；失败、修改选择和恢复服务都不会自动再次提交。
3. **慢提交时确认对象曾可被替换。** 请求期间锁定来源、版本、取消、关闭按钮、遮罩和 Escape，并以同步请求标识防止重复确认；这只锁定界面，不取消后端已提交的执行。正常操作中的“取消 A 再打开 B”路径因此被阻止。跨项目仍沿用既有按项目 ID 卸载工作区的隔离边界，没有新增会话守卫。

名称只从当前页面已经取得的流程、环境资料中匹配。若所选发布版本的对象不在目录中，直接显示该版本绑定的 ID，并注明“名称未加载，以绑定 ID 为准”；不会借用草稿名称，不追加目录抓取，也不因名称缺失增加执行限制。

执行 API、权限、发布与固定版本语义保持原合同：发布版本仍提交 `{ source: 'published', version }`；草稿仍需显式确认，并提交 `{ source: 'draft', publish_draft: true, expected_draft_fingerprint }`。本批不修改后端、数据库、诊断采集、日志或脱敏策略。
