# 第十批整改：项目治理

依据[完整审计 M06](../../audits/2026-10-19/complete-audit.md#m06)和[实施方案 M06](../../audits/2026-10-19/remediation-plan.md#m06)，落实 F-PRJ-01、F-PRJ-02。两项均已实现并完成最终完整检查、专项及浏览器验证。本文件不替代冻结审计和实施方案。

## F-PRJ-01：可追踪的审计历史

- 审计列表使用服务端分页和真实总数，默认每页50条。`auditPage`、`auditAction`保存在URL，动作精确筛选后回到第1页，刷新保留范围，不把非法页码悄悄改为其他记录。
- 操作者同时显示当前名称和稳定用户ID；名称来自按页批量查询，界面说明其为当前显示名，不冒充历史名称快照。原记录和采集过程不变。
- 列表显示资源名称（已有details提供时）、类型、ID及可复制Trace ID。详情只读展示授权API已经返回的字段和变更内容；旧记录缺操作者或Trace ID时显示“未提供”。
- 资源定位只接受当前项目、合法UUID和已实现的接口、工作流、执行报告及项目页面映射。先调用对应受权读取接口，成功且结束刷新后才展示入口；403/404不产生链接。未知资源类型不猜测地址。导航时关闭详情，详情按钮支持键盘Enter。
- 失败显示标准错误和Trace ID，保留动作筛选与输入，并提供重试；不把读取失败伪装成空日志。
- 后端按创建时间和ID倒序排序，避免同一时间记录在跨页时重复或遗漏。名称查询按当前页批量进行，不新增数据库字段或审计采集。

## F-PRJ-02：按权限选择成员和团队

- 项目成员显示姓名、邮箱、ID和角色；团队授权直接携带团队名，团队成员携带身份摘要，不再依赖“当前目录页恰好包含该用户/团队”。旧服务返回缺省摘要时明确说明未提供。
- 项目用户、授权团队、管理员团队选择及团队用户选择使用同一分页搜索控件，每页20条，保留选中项，切换搜索时隔离旧结果和旧错误，保留高级UUID输入。
- 普通Owner的候选人搜索先验证项目的成员管理权限，仅发现项目所在组织的有效用户及已有项目成员；系统管理员可查询已有全局目录。Viewer不能搜索候选人；普通Owner仍不能读取管理员 `/users` 或团队成员目录。
- 用户和团队搜索使用受权只读POST合同；姓名、邮箱搜索词放在请求体，不额外加入URL或访问日志。字符串匹配按字面处理通配符，页码、每页数量、字段和搜索长度有明确约束。
- 项目成员、团队授权、团队成员及搜索目录分别显示错误和重试。成员/授权/团队成员列表读取失败时禁用相关写操作，保留表单选择；目录失败可重试，也可沿用既有的已知ID输入及后端授权校验。
- 权限读取失败后不沿用缓存中的管理能力提交修改；管理员用户/团队入口仍按原有身份裁剪。切项目及组件卸载后的迟到响应不改变新上下文选择或显示旧成功提示。
- 长名称和邮箱选中后限制控件宽度，防止手机页面被选择器撑宽；角色选择提供可访问名称。创建团队后显式选中新团队，未选择管理团队时不擅自操作目录第一页的第一个团队。

## 接口及兼容边界

| 合同                                           | 权限与用途                                                       |
| ---------------------------------------------- | ---------------------------------------------------------------- |
| `GET /projects/{id}/audit-logs`                | 保留原审计查看权限、分页和action筛选，新增可空的当前操作者显示名 |
| `POST /projects/{id}/member-candidates/search` | 成员管理权限；仅返回id、姓名、邮箱、是否有效四个候选人字段       |
| `POST /users/search`                           | 保留系统管理员边界，不向普通Owner开放全量用户目录                |
| `POST /teams/search`                           | 复用原有受登录保护的团队元数据读取范围，增加搜索和分页           |
| 原成员、团队授权及团队成员GET                  | 增加可空摘要字段；原写接口、角色、配额和最后一个Owner保护保持    |

路由只适配请求和响应；授权、目录范围及摘要投影放在服务层，SQL过滤和批量读取放在仓储。无需迁移。不改变执行引擎、工作流环境语义、Secret只写边界、默认脱敏状态或日志采集范围。
