## 2. 接口管理

对应 `F-API-01/02/03/05`，以及 `F-API-04` 的范围说明。

- 已保存断言与执行输入一致；已有断言时显示真正使用的规则，避免“预期201、实际200仍通过”却没有解释。没有保存断言时才提供快速预期状态码。
- 接口目录显示 Method 和 Path。列表 DTO 在服务层批量补充当前版本摘要，不增加每一行的浏览器请求。
- 请求与响应可左右并排或上下分栏，目录与响应可折叠；两个分隔条支持拖动、方向键、Home/End。偏好按 origin、用户、项目隔离。尺寸限制、损坏数据和浏览器存储失败都有回退。
- 手机使用目录、请求、响应面板切换；切换不卸载请求组件，不清草稿，不重发请求。空间按工作区实际距视口顶部的位置分配，移除叠加的固定最小高度。
- Bearer、Basic 和 API Key 使用具名字段；API Key 支持服务端已有的 Header、Query、Cookie 位置。提交校验不依赖先打开 Auth 页。高级字段保留，值的 ON/OFF 行为沿用既有策略，没有新增 Secret 读取。
- 导出前明确“整个项目”及格式，说明分组、搜索、勾选不影响范围。**尚未实现分组/所选范围的服务端导出**，界面没有冒充支持。

## 3. 流程编排

对应 `F-WF-01/02/03/04`。

- 区域中的普通节点复用主检查器，API 节点可以维护 Service Override、Endpoint Variant、节点请求覆盖、超时/重试等已有能力。没有增加节点级独立 environment_id，仍是一条工作流选择一个环境，节点选择该环境内不同 Service/Variant。
- 区域节点有独立编辑会话；关闭区域、切换节点和关闭祖先区域均保护待应用输入。原始 JSON 必须先应用，不能因应用节点或结构动作悄悄丢失。
- 常用可视化条件、状态、区域操作优先，高级 JSON 默认折叠。JSON 应用、节点应用、保存草稿、发布服务器草稿和执行仍是不同动作。
- 摘要覆盖请求固定版本、条件组合与一元判断、循环集合/退出条件、分支、策略、旧版提取/断言/遍历。无法匹配固定版本的请求信息明确缺失，不拿当前版本冒充历史固定版本。长值明确标出省略，完整配置可在检查器阅读。
- 实测发现的区域弹窗字段布局、画布被侧栏裁切及单节点过度放大已修复：画布与检查器分区，弹窗高度受视口限制，容器缩放时重新适应，默认最大缩放为1。

区域检查器复用的是既有能力，不代表新增了 API 节点通用断言合同。工作流 API 节点的状态码规则与独立 Assert 节点仍按现有引擎合同执行，不宣称自动继承接口单次调试断言。

## 4. 用例与报告

对应 `F-CASE-01/02/03`、`F-REP-01/03/05`。

- 新建用例前明确无权限、缺已发布流程、缺环境、加载中及查询失败，并提供相应入口。
- 用例集关闭可继续编辑或明确丢弃；草稿按用户/项目/用例集保存于当前会话。异步保存防重复，失败保留输入；旧保存完成不能清除后续重新打开时产生的新编辑。
- 用例、用例集和批量移动显示目录完整层级路径；失效目录提示重新选择。
- 报告默认定位失败或已执行的业务节点，并将节点与尝试规范写入URL；报告和只读画布保留同一次执行、节点和尝试。无效显式节点提示缺失，避免静默显示另一个节点。切换节点清除旧实例/分支定位。
- 报告和画布复用响应阅读器：完整已捕获内容搜索、原行号、格式化与换行、复制和下载；预览上限不会被当成采集总量。
- 检查点日志按当前节点/实例及检查点尝试在服务端过滤，列表与 total 同范围，分页和选择随范围重置。检查点尝试与 HTTP 重试分别标识。

高级筛选、报告趋势统一范围及冻结断言来源定位仍在后续项中，见进度表，不能由上述修复推断已经完成。
