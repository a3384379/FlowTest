# 自测 CI 的分批执行与证据边界

`scripts/selftest_ci.py` 使用受信检出的 H/O，候选源码仅进入容器构建。普通 PR 遵循受信风险计划和正式 Required Gate；本地 bootstrap review 的 `local_untrusted` 收据不能发布正式门禁。模型调用为 0。

每种部署形态按顺序运行独立波次。各波次复用本形态的精确候选、Mock 镜像与应用源码摘要，使用不同项目、nonce、网络、容器和卷。不能将不同形态的镜像 ID 互换。

1. 基线：10 批原生执行（MCP 核心连续两轮），协议 34、治理 42、运行故障 15，以及独立 O 抗误绿副本 28。先完成全部配置，再冻结需要销毁的运行身份；停止所属栈后核验精确处置。
2. 常规扩展：错误目标成对验证 3、真实 SDK 传输故障 14、设计质量 18、治理恢复/Preview 12、语义反证 5、契约增量/槽位 7、原生控制流 3、安全边界 5、安装恢复 3。所有授权配置完成后再冻结容器身份，最终处置是通过条件。
3. 认证过期：另建 TTL 为一分钟的专用目标，实际等待过期并核对 `ACCESS_TOKEN_EXPIRED`。其余目标仍为十五分钟。
4. Full/Compact worker 故障：双 OS 进程争抢、重复 Celery 消息、两处 SIGKILL，共 4 场景。Standalone 没有 Celery，此波次明确不适用；其 15 个一般运行故障仍必跑，以 4 个真实阻塞工作流占满本地并发槽。
5. 产品与编译：另建独立栈运行产品边界 27 和纯编译/Quick/FlowSpec 草稿链路 38。普通用户、H、O 分别持有最小权限；O 单独进程重算，不读取管理员凭据。编译草稿不会发布或执行；产品边界中的两个真实 core 批次保留 4 个原始失败，独立核验分别匹配。

每包预算不超过 600 秒、500 次目标请求、100 次工具调用，递归深度 1。分波次不延长冻结证据的截止时间。未知写入不盲目重试；失败尝试保留，新尝试使用新目录。

实际 SDK 收包可能跨越容器与宿主时钟的微小差异。H 仅在提前量不超过本次请求及解码实际耗时、0.25 秒和剩余 TTL 三者最小值时，隔离该页直至其时间真正到达；不重发 HTTP，不改时间戳，不放宽原始未来时间/TTL 校验。远未来页仍拒绝。

Standalone 通过 `stack_clone.py` 复用已校验的镜像收据。Full/Compact 引用同一构建；源码、依赖、归属、镜像及处置身份变化都阻断。Docker 地址池不足时只清理本任务归属的环境并串行运行，不 prune 日常网络，不改 Docker 配置。

`ci-receipt.json` 只表示基线，`ci-extended-receipt.json` 表示额外 12 包（Standalone）或 13 包（Full/Compact）。整个入口只有各包通过且所有专用环境清理完成才返回 0。处置前返回 2 的报告与最终报告分别保留。

上传白名单是六个精确目录：预检 `public/`，运行根 `public/`、`extensions/public/`、`expiry/public/`、`workers/public/`、`product/public/`。仅上传身份摘要、独立报告、JUnit；不上传环境、凭据、原始 SDK 会话、安装状态或业务响应。原始执行失败、独立匹配、证据完整性、信任及清理分别记录。

治理路径变更仍需维护者受控 Bootstrap。独立 Bootstrap workflow 只提供检查，不发布正式 Required Gate，不修改保护规则。Windows 原生包、远程当前提交门禁、合并后 CI、真实 Host/LLM 和完整发布验收需要各自证据，不能从本地通过推断。
