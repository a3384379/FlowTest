# 自测方案前端完整性审计

审计日期：2026-10-25。范围由用户确认：本轮自测方案涉及的全部前端链路，包含接入、初始化、生成、审核发布、原生资产、批次历史、报告、来源、辅助修订与关联权限。不是全站所有模块的审计。

本文件保留审计时的问题快照；后续实施与验证见[审计修复记录](frontend-audit-remediation-20261025.md)。

## 结论与基线

**当前前端不能判定为按方案完整交付。** 基础执行、权限和来源校验已实现，但产品链路仍有功能遗漏和可复现的状态、刷新、导航问题。

- 基线为 `codex/mcp-native-selftest` / `c4e2a5f58fb2f13e4295f2bd790830f5ed8ef073`，包含审计前已存在的六项接入引导修改；这些修改没有撤销。
- 对 `frontend/src/features/self-test/` 的 28 个生产组件、契约、辅助模块和样式文件纳入核对，并检查质量中心、审核、工作流、原生资产、报告、组织权限配置中的相关集成入口。
- 需求基线：用户交付的《FlowTest_自测界面设计规格》v2、《FlowTest_自我验证体系_完整开发方案》v2，以及仓库中的产品、编译、辅助修订说明。
- 确认 **11 项问题：2 项 P1、9 项 P2**。其中 7 项问题有运行复现，4 项属于源码与接口契约共同确认的功能缺口；运行复现共 9 个场景。
- 原有 13 个命名测试文件、210 项回归全部通过。专项复现测试的断言刻意验证问题现状；其 9 项通过表示问题成功复现，不能记为产品验收通过。

本次只审计，没有修复以下问题，没有替换运行镜像、改变部署绑定或调用模型。

## 问题清单

### FT-UI-01 · P1 · 生成未执行却把正式执行画成已完成

- **触发与影响**：生成已阻断、批次已封存、`plan_run_ids=[]` 时，进度条仍把“发布固定版本”“正式执行”等前序步骤标成完成；同页又写“尚无正式执行”。后端 verdict 没有被改成通过，但执行事实的呈现互相矛盾。
- **源码**：`frontend/src/features/self-test/SelfTestGenerationProgress.tsx:6–19,39–51` 根据 `phase=completed` 直接选择最后一步，没有核对实际提案、固定来源和 Run。
- **可达性**：`backend/app/services/self_test_agents.py:360` 允许无 Run 的终态核对；核验封存时在 `:796` 设置 `phase=completed`，该阶段只表示批次收尾，不能证明所有生成和执行步骤发生。
- **证据**：专项场景“marks formal execution finished for a sealed blocked generation with zero native runs”。
- **修复要求**：按真实阶段、回执、发布资源与 Run 分别呈现完成、阻断、取消或未执行。封存失败不得把未发生阶段补成完成。

### FT-UI-02 · P1 · 辅助修订只有展示，没有可操作的前端链路

- **缺口与影响**：已有 `SelfTestAssistedSource` 展示修订结果，但用户不能在页面创建辅助修订批次，也不能经页面提交该批次的人工 Case 提案；无法按方案完成“保留首次失败 → 人工修订 → 新审核版本 → 独立重跑”。
- **源码**：`frontend/src/features/self-test/self-test-contract.ts:470–473` 的生成请求没有 `assisted_before_batch_id`；`SelfTestBatchDrawer.tsx` 的提交体也不传；`self-test-service.ts` 没有辅助 Case 提案调用，前端全量检索无对应请求入口。
- **既有后端**：`backend/app/schemas/self_tests.py:241–244` 已接收修订前批次；`backend/app/api/v1/endpoints/self_tests.py:440–454` 已提供 `assisted-case-proposals`，产品约束见 [assisted-revisions.md](assisted-revisions.md)。
- **证据类型**：源码与接口契约确认，未调用真实模型。
- **修复要求**：补任务创建、原批次选择/校验、差异及原因、既有审核发布入口与新批次运行；首次生成与修订指标分开，不能覆盖原证据。

### FT-UI-03 · P2 · 安装资源没有详情入口，来源中的固定资产不可导航

- **触发与影响**：安装成功后，API 返回完整环境、Workflow/Case 固定版本映射，但页面只显示安装状态；批次来源链也把 Workflow/Case ID 当普通文字。用户很难查看实际安装了哪些资产、进入哪个固定版本。
- **源码**：`self-test-contract.ts:150–181` 接收安装 `mapping`，生产组件没有消费它；`SelfTestWorkspace.tsx:553–603` 只显示安装状态；`SelfTestSourceChain.tsx:74–82` 与 `SelfTestResourceSnapshot.tsx` 只有 ID/版本文字。
- **证据**：专项“does not expose installation asset details…”与“shows fixed Workflow and Case references as plain text…”。
- **修复要求**：提供“查看安装”，展示已授权映射与失败资源；复用现有资产详情、固定版本及历史流程入口。不能跳到最新草稿冒充冻结版本。

### FT-UI-04 · P2 · 报告里的独立核验不会跟随 Observer 完成而更新

- **触发与影响**：在独立核验未完成时打开报告，随后 O 已将同一关系更新为 matched，当前页仍显示 pending；在页面持续聚焦、不重新进入的情况下不会主动重新读取。
- **源码**：`SelfTestReportPanels.tsx:14–34` 的关系查询没有活动阶段轮询或局部刷新控制；父报告的重读原生执行也不负责刷新这个独立查询。
- **证据**：专项等待 2.3 秒，关系请求仍只有一次、画面保留 pending；手动使该查询失效后立刻得到 matched。
- **修复要求**：活动核验阶段进行有界轮询，终态停止；提供局部重试/刷新，并保留项目、身份 epoch 和精确执行关系约束。

### FT-UI-05 · P2 · “刷新状态”没有刷新生成状态和历史批次

- **触发与影响**：后端生成回执或历史目录已更新，点击“刷新状态”后仍显示旧工具计数、旧提案或旧历史；终态停止自动轮询后尤其明显。
- **源码**：`SelfTestWorkspace.tsx:425–434` 只刷新 binding、权限、安装、batch 和 scenarios，遗漏 `generation` 和 `runs`。
- **证据**：专项确认 batch 被重新请求，而 generation、history 的读取次数均保持 1。
- **修复要求**：按当前有效选择刷新所有相关只读查询，显示刷新失败；不要把批次摘要重读成功当作整个工作台已更新。

### FT-UI-06 · P2 · 审核、发布、报告往返会丢失自测上下文

- **触发与影响**：从自测进入 MCP 审核后，点击物化 Case 的链接会丢失 `selfTestBatch`；FlowSpec 应用后，回链仅在已关闭的审核弹窗内。报告的返回链接还丢失原分类、核验筛选、页码及历史游标。
- **源码**：`frontend/src/features/mcp/MCPMaterializedResult.tsx:42–68` 重新构造资源 URL，没有携带已核验自测上下文；`frontend/src/pages/WorkflowsPage.tsx:197–209,575–578` 关闭提案弹窗，而回链只存在于弹窗。`self-test-navigation.ts:51–57` 只恢复 mode、batch 和 scenario。
- **证据**：专项“drops the originating self-test batch…”与“returns from a report without the originating filters…”。
- **修复要求**：定义受校验的内部返回上下文，在审核、物化、发布、报告各跳转间传递；发布页面保留已核验的返回入口。不接受任意外部 return URL。

### FT-UI-07 · P2 · 编译诊断和待补输入缺少可读详情

- **缺口与影响**：方案要求展示编译 readiness、必需输入、不支持场景、Oracle 到断言落地诊断。当前只显示阶段、通用 reason code 和发布后来源摘要；阻断时无法在工作台逐项定位缺什么、哪个场景/Oracle 需要处理。
- **源码与契约**：`SelfTestGeneration.tsx:21–57`；`self-test-contract.ts:289–301`；`backend/app/schemas/self_tests.py:379–390`。当前 generation 摘要没有结构化 diagnostics 或 Case 模板/slot 的投影，不能只靠增加前端标签完成。
- **证据类型**：对照界面规格 §3.1 和生成 DTO 确认的跨层缺口。
- **修复要求**：提供有界、已授权的诊断与待补输入投影，再接阶段详情及准确下一步；保留严格解码，不扩大日志或暴露原始敏感 payload。

### FT-UI-08 · P2 · 方案中的统计指标尚未产品化

- **缺口与影响**：原生视图要求按 API、引擎符合度、独立核验给出分子/分母；主方案 §6.5 还要求协议可用率、设计合法率、可执行资产生成率、Oracle 落地率、首次符合率、修订后符合率、缺陷检出率、来源完整率八项指标。目前只有预期场景数、必需场景数、来源数、Run 数和静态能力说明。
- **源码**：`SelfTestWorkspace.tsx:181–190`、`SelfTestGenerationProgress.tsx:55–64`、`SelfTestOverview.tsx:14–50`；现有 generation 摘要也没有这些统计投影。
- **证据类型**：方案与源码确认，属于未实现的产品统计，不是本次模型没运行导致的临时空数据。
- **修复要求**：定义服务端统计范围及有界投影，分别展示分子、分母、版本和排除理由；零分母为未评估，不从当前分页计算全量指标。

### FT-UI-09 · P2 · 独立核验对照仍有固定占位内容

- **缺口与影响**：对照表只对状态和可用的节点错误码做实际呈现；请求次数、分支和迭代永远显示“当前摘要未提供，详见执行与核验证据”。冻结节点、阶段、次数、清理等没有形成方案要求的逐项期望/实际/差异视图，用户仍需手动下载并理解 JSON。
- **源码与契约**：`SelfTestVerificationComparison.tsx:57–66`；`self-test-contract.ts:391–418` 的场景 DTO 没有对应的结构化核验项。
- **证据类型**：源码与 DTO 确认的跨层缺口。占位文案没有伪造实际值，但不能计为对照功能已完成。
- **修复要求**：读取独立核验的有界比较结果，提供逐字段差异与定位；缺证据保持不完整，前端不能自行重新裁决 verdict。

### FT-UI-10 · P2 · 提案来源查询错误被折叠成普通“未核验”

- **触发与影响**：审核页读取自测来源返回 503/403 等标准错误时，用户只看到“当前提案与自测来源尚未核验”，真实错误和 Trace ID 被隐藏，没有相应重试入口。
- **源码**：`SelfTestProposalBacklink.tsx:40–64` 将所有非成功读取当作无法匹配来源，未展示 `generation.error`。
- **证据**：专项返回 `503 / UNAVAILABLE / audit-source-trace`，界面不展示错误信息或 trace。
- **修复要求**：区分加载、读取失败、来源确实不匹配三种状态，复用标准错误展示与只读重试。

### FT-UI-11 · P2 · 初始化已阻断，抽屉仍提示等待宿主

- **触发与影响**：选择“初始化并运行”后，安装查询已返回 blocked 和失败原因，抽屉仍给出 info 提示“初始化任务已创建，等待外部宿主完成”；查询又在 blocked 状态停止轮询。用户缺少失败项、部分映射与明确恢复路径。
- **源码**：`SelfTestSetupDrawer.tsx:199–217` 把除 ready 以外的所有状态合为等待；`:396–404` 在 blocked 停止轮询；没有方案要求的“继续初始化”交互。服务端对已存在安装的 install 请求返回原安装，不能把重新点初始化当作已经实现恢复。
- **证据**：专项经真实组件交互与 MSW 状态转换，确认 blocked 已读回，抽屉继续显示等待，且没有“继续初始化”；没有错误地启动原生 Run。
- **修复要求**：分别展示 needs_input、queued、installing、ready、blocked、archived 及原因；恢复必须绑定原安装、journal 和已完成映射，必要时补后端明确恢复契约，不能另建资源掩盖部分失败。

## 不计为本次缺陷的边界

- 当前日常环境没有登记 binding/H/O，导致执行按钮不可用；这是部署状态，不等于执行按钮未开发。登记入口的发现性上一轮已修复。
- 浏览器不直接启动 Docker、本机 Codex 或自行授予代理权限，符合方案的信任边界；不能用增加任意 URL 表单来绕开登记。
- 真实 Host/LLM 按用户约束未调用；不将其 NOT_RUN 算作确定性 MCP 失败或伪造为验收通过。
- 设计图中的示例批次和统计不应直接填入日常空环境。
- 普通报告自动发现自测关联所需的 `self_test_refs` 尚未提供；方案允许首期使用经校验的自测深链，本次不把这个可选能力单独算作代码缺陷。
