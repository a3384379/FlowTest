# 人工修订与独立重跑

人工修订使用新的批次。原批次、第一次模型调用、原生失败、原审核提案与原发布版本保留；新结果单独标注“辅助重跑，不计首次生成”。模型生成指标与修订后符合率分开统计。

## 固定修订任务

在现有 `generation-batches` 请求中指定 `generation_mode=host_llm_mcp` 和 `assisted_before_batch_id`。该引用进入冻结 manifest 和其摘要，不能在物化时临时替换。原批次必须属于同一项目、安装和环境绑定，已经封存，具有全部所选场景的固定可执行来源，证据仍可用且清理完成。新批次须保留完整场景集合。

H/O 的领取响应只投影当前任务需要的原批次与最初模型批次来源，包括发布引用、内容摘要和受权限保护的 artifact 引用。没有给 O 增加项目普通查看者或写入凭据。原失败发生在可执行来源形成之前时，返回 `SELFTEST_ASSISTED_BEFORE_SOURCE_MISSING`，不能猜造原版本或审核证据。

## 真实编辑、审核与发布

Workflow 继续使用既有 FlowSpec 导入、可视化审核、应用草稿和发布版本。人工 Case 提案使用普通用户入口：

`POST /api/v1/projects/{project_id}/self-tests/runs/{batch_id}/assisted-case-proposals`

该入口仅接受项目可编辑用户和当前冻结修订任务，复用受控写入的类型、风险治理和幂等处理，并记录 `actor_type=user`、当前批次和真实编辑者。机器 MCP 身份不能调用此普通用户入口。审核继续走现有受控变更集的批准、接受和发布路径；不会自动批准。

每项修订来源必须保留原 Design、编译、API、Oracle 与模型调用记录。新的 Workflow 和 Case 均需要新的真实审核提案和发布引用。必要 assertion 的比较、值、阶段和运行条件必须保持；名称和画布位置不影响原必要断言语义。逐字段差异由真实固定发布定义重算，最多 200 项，不会截断后当成完整结果。

`assisted.authorization_digest` 是本次修订任务的新授权摘要，必须在部署 principal 的明确白名单中。旧 `host_evidence` 保留原宿主、模型、Skill、提示和预算授权；本次修订工具计数为零，不重复计算旧模型调用，也不能伪称新模型生成。

## 执行与证据保留

物化结果先校验原来源、编辑与审核者、全部发布关系和差异，再冻结新的 Suite、Plan 与展开快照。正式执行前再次检查原证据可用性，用户确认本次资源和环境摘要后才创建原生 Run。

原批次的物理 artifact 或执行元数据过期时，后续修订批次当前投影也会阻断通过；已经封存的历史 verdict 保留。祖先遍历有界，并共享当前请求的存储可用性探测预算，不下载完整内容。

自动化审核驱动器属于 `ci_fixture`，不是实际人工验收。带合成原批次封存的 API 测试只证明声明的契约与真实后续 API/Run 行为，不能冒充已执行的真实模型或人工现场验收。
