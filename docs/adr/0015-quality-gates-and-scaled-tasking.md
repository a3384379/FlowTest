# ADR 0015：Cron 调度、质量门禁与持久队列容量

## 状态

已接受，S19 实施。

## 决策

- Test Plan 的周期调度使用五字段 Cron 和显式 IANA 时区，存储的下一次运行时间统一为 UTC；同一计划不能同时配置固定间隔与 Cron，最短周期为 60 秒。
- 队列优先级固定为 0～9，任务按 `general`、`data`、`ai` 三个逻辑队列路由。单机 Compose 为三个队列运行独立 Worker，控制面仍以 PostgreSQL 中的 Run 状态为事实源。
- 项目并发与排队配额在持有项目行锁时检查，避免多个 API 实例同时越过上限。达到运行配额的任务延后执行，达到排队上限的创建请求明确失败。
- Flaky 记录按发布目标和版本唯一聚合，使用数据库 Upsert 与行锁保证并发更新确定；隔离仅影响后续 Test Plan Snapshot，历史运行不变。
- Quality Gate 从已完成 Run、固定基线、Flaky 和契约 Breaking Change 派生，保存一次不可变 Evaluation。CI 接口只消费已持久化结果，不在请求内重跑测试。
- JUnit XML 由结构化执行数据通过 XML 库生成，用户输入不参与模板拼接。

## 后果

- Cron 在夏令时切换时遵循所选 IANA 时区规则，API 返回的时间仍为 UTC。
- 多 Worker 能提高吞吐，但同一项目仍受显式并发和排队配额约束。
- 隔离资产不会计入阻断失败，仍保留运行项及隔离标记，避免静默丢失测试覆盖。
- S20 可在这些持久化队列和质量结果之上增加 Worker 指标、Trace 和企业身份能力。
