# ADR 0009：治理权限、出站网络与幂等边界

## 状态

已接受（S10）

## 决策

1. 项目权限固定为 Owner、Editor、Viewer；System Admin 绕过项目成员关系。能力通过领域枚举映射，路由只声明所需能力，不自行判断角色。
2. Owner 和 System Admin 可维护项目出站域名与私网 CIDR。所有 HTTP 目标在发送前解析 DNS，并逐个校验解析地址；回环、链路本地、元数据、组播、未指定及保留地址始终拒绝。
3. 私网目标必须同时命中域名白名单和允许 CIDR。API 调试、Workflow 节点和通知 Webhook 共享同一策略实现，防止执行入口之间产生绕过。
4. Import 先生成不改变 API 资产的 Diff，再按 operation key 显式合并。删除项默认不选中，只有明确合并后才停用；预览原文加密暂存并在合并后清除。
5. 执行类写操作使用 `Idempotency-Key`。项目、操作者、操作和 Key 组成唯一边界；相同请求返回原结果，不同请求冲突，在途请求不会重复执行。
6. 登录、执行和普通写请求使用独立 Redis 限流桶。Redis 暂时不可用时记录告警并放行，避免控制面故障扩大；正常超限统一返回可追踪的 429 错误。
7. 审计详情在写入前统一脱敏并记录 Trace ID。Secret 继续保持只写不可读，接口不返回明文、密文或 nonce。

## 结果

- 权限判断、安全策略和执行一致性成为可单元测试的领域规则，而不是分散在 API 路由中的条件分支。
- 导入变更具备预览、选择、过期检测和幂等重放语义，历史 API 不会因一次预览被意外停用。
- 所有服务端出站请求共享 DNS 重绑定防护，新增执行入口必须显式依赖该策略。
- 幂等记录与限流状态属于基础设施，S11 清理任务负责回收过期幂等记录。
