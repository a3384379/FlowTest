# ADR 0029：隐私安全诊断与可恢复回滚证据

状态：Accepted
日期：2026-08-19

## 背景

Compact 进入公司环境后，研发通常无法直接访问服务器。直接收集 `docker inspect`、容器环境、
原始日志或业务 Dump 虽然方便排障，却容易把访问凭据、Secret、请求正文和客户数据带入工单。
另一方面，只验证备份文件存在，不能证明恢复后一次性写入确实消失，也不能证明恢复后的应用仍可写入。

## 决策

1. 支持诊断采用固定文件和字段白名单；只收集公开健康响应、版本、6 个服务的安全状态字段、
   资源上限及 PostgreSQL/Redis/MinIO 聚合值。禁止收集部署配置、容器环境、原始日志、对象 Key/内容、
   项目名称以及请求/响应正文。
2. 每个诊断探针单独记录退出码。局部服务失败时保留空的固定结果文件和失败状态，不通过扩大采集范围
   兜底。诊断目录必须拒绝未知文件和符号链接，并以逐文件 SHA-256 自校验。
3. MinIO 诊断只通过应用运维模块返回对象数量和总字节数；该只读动作不会创建 Bucket，也不输出对象 Key。
4. 工具只生成本地目录，不自动上传。人工发送前仍须执行公司数据分级检查，并使用批准的交换渠道。
5. 回滚演练先生成 PostgreSQL + MinIO 一致性备份，再写入一次性 Project/Artifact，覆盖恢复后验证其
   不存在；随后验证恢复后仍可写入，并再次恢复同一基线，保证演练成功时不遗留探针业务数据。
6. 演练中断时自动尝试恢复；失败则保留备份并明确要求停止写入、人工恢复。跨迁移版本仍禁止只切换旧镜像。

## 结果

公司运维可以在不披露原始业务数据和部署凭据的前提下交接最小诊断证据，并用机器可读结果证明备份
确实可回滚且恢复后应用可继续写入。字段白名单会降低远程排障的信息量，必要的日志必须另走单独审批，
不能临时塞入支持包。该自动化不替代真实 72 小时试点、维护窗口审批或正式 RC。
