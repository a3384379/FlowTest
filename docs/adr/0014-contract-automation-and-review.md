# ADR 0014：契约生成、破坏性变更与人工审核

状态：Accepted

## 背景

OpenAPI 重导入已能管理 API 资产，但它不会自动产生边界、异常和属性测试，也无法告诉团队新文档是否破坏现有调用方。直接执行生成结果会让未确认请求离开平台，并把不可预期的 Schema 复杂度引入 API 进程。

## 决策

1. Contract Run 保存项目、来源摘要、规范化 Schema、基线、Diff、Breaking Change 和 Schema 覆盖率；历史运行不随后续上传变化。
2. 同名文档默认使用最近完成运行作为基线，也可显式指定同项目基线。破坏性规则首批覆盖操作删除、新增必填请求字段、请求/响应类型变化、成功响应删除和响应字段删除。
3. Schemathesis 负责 OpenAPI 语义验证和正向/负向属性样例生成；FlowTest 额外生成声明式边界草稿。生成定义记录 Schema SHA-256、引擎版本、操作键和标准检查项。
4. 所有生成结果初始为 `pending`，只能从该状态单次转移到 `accepted` 或 `rejected`。人工可在接受前编辑名称、定义和备注；未确认草稿没有执行入口。
5. 审核端点使用行锁和完整项目授权，记录审核人、UTC 时间、决策和审计事件，防止重放或跨项目审核。
6. 文档限制为 5 MB、64 层、10 万节点和 500 个操作；只接受 UTF-8 JSON/YAML 的 OpenAPI 3.x 或 Swagger 2.0，禁止外部 `$ref`。编辑后的生成定义限制为 256 KB 并验证固定字段形状。
7. 文档和生成请求按不可信输入处理；外部引用、Schema Bomb 和超限输入在生成前拒绝，Header/Cookie/Token/Secret 样例使用统一脱敏器。校验器异常不向客户端返回内部栈或文档片段。

## 结果

- 文档变更会生成可审阅的 Diff、破坏性证据和草稿，不会隐式改动已发布资产。
- 生成程序的资源边界和人工门禁是执行的前置条件，后续 S19 Quality Gate 可直接消费 Breaking Change 和覆盖率结果。
- 未来增加 GraphQL、Proto 或 Pact 时，继续复用不可变运行、生成草稿、显式审核、项目隔离和资源上限协议。
