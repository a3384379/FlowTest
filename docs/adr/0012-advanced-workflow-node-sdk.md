# ADR 0012：高级工作流节点、固定子流程快照与安全表达式

状态：Accepted

## 背景

SubFlow 与 ForEach 会把一个 Workflow 的运行边界扩展到另一个已发布版本，并允许同一版本被并发调用。若执行时回读最新草稿、直接解释用户脚本或让框架任务对象承担领域调度，历史结果会漂移，调试行为也无法稳定复现。

## 决策

1. Node SDK V2 使用显式类型的 Handler Registry；调度器只依赖节点执行协议，不依赖 FastAPI、Celery 或 ORM。
2. SubFlow 只能引用同项目的已发布版本。父 Workflow 发布与执行准备时递归固定子流程定义、指纹、API Snapshot 和其下级子流程，执行期间不回读最新版本。
3. 发布时按 Workflow ID 校验跨流程调用图，禁止直接或间接递归，最大嵌套深度为 5。
4. ForEach 只从已完成的上游节点读取数据，并使用受限 JMESPath 表达式取得数组；最多 1000 项，默认并发 5、最大并发 20。`fail_fast=false` 仅表示继续处理剩余项，任一子项失败后 ForEach 仍汇总为失败。
5. 循环元素和索引作为有来源的 Runtime 变量传给固定子流程。子流程需从 Start 节点输出通过字段映射传入 API/其他节点；不提供 Python/JavaScript 或动态求值。
6. 断点调试只运行目标节点及其祖先，不持久化为正式 Execution；节点重放从既有 Execution 的加密固定运行计划恢复目标及其祖先。两者统一脱敏并写入审计。
7. 当前版本不允许 SubFlow 引用含 Dataset 节点的 Workflow。Dataset 的父子执行持久化语义与嵌套循环聚合需要独立协议，留待后续兼容扩展；发布时会返回明确错误，不静默降级。
8. 前端画布历史只记录定义变更，不记录选择态；复制粘贴产生新节点 ID，撤销/重做最多保留 50 个状态，自动布局不改变业务连接。

## 结果

- 父流程历史执行不受任一子流程后续草稿或发布影响。
- 子流程、循环、断点与重放复用同一节点协议和脱敏边界，新增节点无需修改调度器分支。
- 安全表达式有明确输入、输出和资源上限，平台继续不执行用户脚本。
- 嵌套 Dataset 是显式受控限制；解除限制前必须先定义父执行、行执行和循环项之间的持久化与报告关系。
