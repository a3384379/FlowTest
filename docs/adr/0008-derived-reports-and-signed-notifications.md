# ADR 0008：派生报告与签名通知

## 状态

已接受（S9）

## 决策

1. 执行报告从不可变 Execution Snapshot、Node Execution 和 Execution Context 派生，不另存一份会与执行事实漂移的报告明细。
2. 报告接口统一返回执行汇总、步骤级脱敏请求/响应、提取/断言结果、变量映射轨迹和数据集子执行。
3. 失败分类由稳定错误码确定为断言、超时、网络、HTTP 4xx、HTTP 5xx、配置、取消或运行错误；趋势按 UTC 日期聚合。
4. HTML 导出只包含脱敏快照和节点输出，作为 `report` 类型 Artifact 存入 MinIO，并复用项目授权下载链路。
5. 通知 Webhook Secret 只在创建响应返回一次，使用 AES-256-GCM 加密保存；列表、详情、日志和投递记录都不返回 Secret。
6. 通知请求对 `timestamp.body` 使用 HMAC-SHA256 签名，固定 JSON 序列化并携带事件类型；每次投递记录 HTTP 状态或稳定错误类别。
7. Workflow 和 Test Plan 到达终态后由 Worker 发送通知；通知失败不修改测试执行事实，也不会将已完成执行回滚为失败。

## 结果

- 报告与执行记录保持单一事实来源，历史快照天然支持审计和可重复导出。
- 通知消费者可验证消息完整性和来源，并能通过投递历史排查失败。
- 趋势读取当前采用项目范围查询；S11 的容量测试将决定是否增加预聚合表。
